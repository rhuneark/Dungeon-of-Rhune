# Dungeon of Rhune (Pixi.js v8 + React 19 + Tailwind v4 + Electron)

Ships on **Steam** (Electron desktop shell, `desktop/`) and the **web** (static `dist/`). There is no RUN.game anymore — never re-add its SDK.

## File Structure (Dungeon of Rhune)

- **src/main.tsx** — Entry point. The boot sequence, numbered 0–7; the ORDER matters (resolvers/resize → platform init → save load → React mount → boot-cover lift → asset+font warm → menu → lifecycle/flush hooks). Don't reorder. Dev builds expose `window.__rhune` (session, store, simulateDrops, platform) for console/Playwright poking.
- **src/platform/index.ts** — The only outside-world API: `platform.storage` (desktop: files via the shell; web: localStorage), `fullscreen`, `quit` (desktop), `onFlushRequest`, `achievements.unlock`, `steam`, `devTools`. `initPlatform()` never throws; the game must run identically with or without Steam.
- **desktop/** — Electron shell: `main.cjs` (app:// protocol over `dist/`, strict CSP, save files in userData/saves with atomic write + .bak, fullscreen settings, flush-before-close handshake, steamworks.js), `preload.cjs` (`window.rhuneHost` bridge — keep in sync with the `HostBridge` interface), `steam.config.json` (App ID; 0 = no Steam), `dev.mjs` (`npm run desktop:dev`).
- **electron-builder.yml** — `dist:win|linux|mac` → plain app folders in `release/` (SteamPipe uploads those). **steam/** — SteamPipe `.vdf` templates. **STEAM.md** — the release guide.
- **src/content/achievements.ts** — Steam achievements as pure checks over the save (unlocked in `session.commit()`).
- **src/state/store.ts** — UI-facing store (`useSyncExternalStore`): phase, view metrics, open panels (`left` / `right` / `overlay`), dialog, toasts, hover name. `store.patch({...})` anywhere; `useStore(selector)` in components.
- **src/state/session.ts** — Owns the mutable `SaveData`. Mutate `session.hero` / `session.save`, then `session.commit()` (bumps `store.rev`, debounced autosave). `session.sheet()` = cached character stat sheet. `useSession()` re-renders on any save change.
- **src/view/viewport.ts** — Pixel-perfect math: device-aligned frame rect, integer world `zoom` (device px per world px, ~480 world px tall) and `ui` scale (integer, except 1.5 for 645–860 device-px-tall windows; UI canvas ≥ 690×430 UI px). Player overrides (Options panel, `O`) persist in localStorage `rhune_view_prefs`.
- **src/content/** — Pure data (the design): `stats.ts` registry, `items/` (bases, affixes, uniques+quirks, rhunes+rhunewords, rare names), `loot/treasureClasses.ts`, `skills/` (Disciplines, skills, trees), `lore/` (lore entries, lore quests), `npcs.ts`.
- **src/systems/** — Rules over the data, no rendering: itemGen, loot (TCs + Fortune), itemText (derived item view/prices), character (stat sheet), actions (item flow/cursor/sockets/identify/sell), economy (vendors, gambling, well, crucible), skills, quests, progression, hero (save types), inventory (grid ops), save, rng.
- **src/assets/** — `art.generated.ts` (GENERATED by tools/art/pack.py), `manifest.ts` (built from it; all art is critical), `preload.ts` (warms art + forces the pixel fonts to load before Pixi Text).
- **src/game/pixiApp.ts** — Pixi app for pixel art: nearest scaling, no AA, roundPixels, renderer sized from view metrics (not `resizeTo`). Imports `pixi.js/unsafe-eval` because the desktop CSP forbids eval — keep it.
- **src/game/stage.ts** — World stage in WORLD PIXELS + camera (`lookAt`, `screenToWorld`), offset snapped to device pixels.
- **src/game/GameCanvas.tsx** — React ↔ Pixi boundary; mounts the town scene, resizes in place on view changes, freezes the ticker while paused.
- **src/game/engine/** — `nav.ts` (walk grid + A*), `tilemap.ts` (terrain painting + Wang corner autotiling), `art.ts` (sheet slicing), `groundItems.ts` (loot pop/labels/beams), `fx.ts` (float text, beams, `pixelText`).
- **src/game/world/** — `zone.ts` (ZoneDef), `thornwick.ts` (the town: terrain, props w/ footprints+actions, NPCs, placed quest items).
- **src/game/scenes/townScene.ts** — Builds a ZoneDef; input (click/hold-to-walk, WASD), player/NPC/goose, ground loot, camera. Keeps the `createXxxScene(...) → { destroy() }` contract.
- **src/game/interact.ts** / **worldBridge.ts** — What clicking things does (dialogs, panels, quest events); bridge for systems to spawn drops / float text in the live scene.
- **src/ui/** — `App.tsx` (frame + integer-scaled `UiRoot` + phase router), `PlayingUi.tsx` (panels + hotkeys), `Hud.tsx`, `kit/` (Panel, GridView, ItemIcon, ItemTooltip, tooltip store, cursor item), `panels/`.
- **src/styles/app.css** — Tailwind, `@theme` palette + fonts, pixel utilities (`t10`, `t20`, `title18`, `s8`, `frame`, `frame-inset`, `pbtn`).
- **tools/art/** — PixelLab pipeline: `spec.py` (prompts) → `gen.py` → `out/` → `pack.py` → `public/art/` + `src/assets/art.generated.ts`. See its README.
- **public/art/** — Packed sprites (chars, tiles, props, icons). **public/og-image.jpg** — web share image. **public/boot-safety.js** — boot-cover fallback (external file so the CSP can forbid inline scripts). **build/icon.png** — app icon.
- **index.html** — Locked viewport, inline-CSS boot cover (+ `boot-safety.js` 4s fade), React root `#root`. No inline scripts (CSP).
- **vite.config.ts** — `base: './'` (required for app:// and static hosting), React + Tailwind, esnext target.

## Key Patterns

- **Layering** — React owns navigation (which screen exists); Pixi owns the game. Both live inside the CSS device frame `#app-frame`, so canvas and DOM UI always align. UI overlays are `pointer-events-none`; controls opt back in.
- **Game → UI** — `store.patch()` on discrete events (score, wave, popups), never per-frame. **UI → game** — a store field the scene reads, or a direct function call into the scene module.
- **Crisp pixels** — The world is in WORLD PIXELS (32px tiles, 64px character canvases); the UI is in UI PIXELS inside `UiRoot` (32px per inventory cell). Both scale by integer device-pixel factors from `view/viewport.ts`. Keep sprites at integer positions, never scale art by non-integers, and use pixel fonts only at native sizes (Jersey 10 at 10/20px, Jacquarda Bastarda 9 at 9/18/36px, Silkscreen at 8px). Pixi Text uses `resolution: 1` (`pixelText`). UI layouts must fit ~800×450 UI px.
- **Content vs systems** — New items/affixes/uniques/rhunes/skills/quests are DATA in `src/content/`; rules live in `src/systems/`. Tooltips and stats are derived (itemText/character), so rebalancing data updates existing saves. Stats are string ids (`res:fire`, `seek:rhune`, `tagPct:projectile`, `skill:<id>`, `quirk:<id>`) — scale by tag/damage type, never by specific skill.
- **Save mutations** — mutate via `session`, then `session.commit()`. Item movement goes through `systems/actions.ts` (cursor/grid/equip/socket rules live there).
- **Platform posture** — Game code only talks to `platform`; never import Electron/Node or `window.rhuneHost` elsewhere. Every host call can fail; the game must boot and play in a plain browser and on desktop without Steam.
- **Lifecycle** — `visibilitychange` hidden → `store.paused` (ticker frozen) + save flush. Desktop window close sends `host:flush`; the renderer flushes then replies (2.5s timeout). Web flushes on `pagehide` (best effort; autosave is debounced 1.5s anyway).
- **Desktop security** — contextIsolation + sandbox, no nodeIntegration, CSP via the app:// handler, navigation locked, external links open in the browser, IPC inputs validated in main. New host features = a validated `ipcMain.handle` + a preload method + the `HostBridge` type.
- **Assets** — Everything ships in `dist/` (critical vs deferred bundles in `src/assets/manifest.ts`, warmed at boot with progress).
- **Dependencies** — Renderer libraries (pixi, react, fonts) are `devDependencies` because Vite bundles them; `dependencies`/`optionalDependencies` are only what the Electron main process needs at runtime (`steamworks.js`, optional so web-only installs never fail). electron-builder ships only those.
- **allowScripts** — package.json `allowScripts` silences npm's install-script warnings (electron downloads its binary); keep entries name-only.

## What to Modify

- **New game logic** → New scene modules in `src/game/scenes/` following the `createXxxScene(app, stage, ...) → { destroy() }` contract; new maps are `ZoneDef`s in `src/game/world/`.
- **New art** → add a prompt to `tools/art/spec.py`, run `gen.py` then `pack.py` (assets are auto-listed in the manifest). Buildings use the FRONT style ("low top-down", facade toward camera) and are sized so doors fit the 64px characters; approved drafts in `tools/art/ref/` steer re-generations. Props anchor on their visible base (bbox bottom), so `y` in a ZoneDef is where they meet the ground; `approachDy` sets where the player stands to use one.
- **Loot tuning** → `src/content/loot/treasureClasses.ts` (TCs + `QUALITY_TUNING`), affix tiers/weights in `content/items/affixes.ts`; check with the Loot Lab (~ key).
- **UI screens / HUD** → React components in `src/ui/`, routed by phase in `App.tsx`; style with Tailwind; game-facing state through `store.patch()`.
- **Title** → `<title>` in index.html + heading strings in `LoadingScreen.tsx` / `MainMenu.tsx` + `name` in package.json.
- **Palette** → the `@theme` block in `src/styles/app.css`.
- **Orientation** → landscape; the frame fills the window with aspect clamped to 4:3–21:9 (`view/viewport.ts`).
- **Save/persistence** → `systems/save.ts` via `platform.storage` (sanitizes stale content ids). Desktop save files live in `<userData>/saves/*.json` (Steam Auto-Cloud paths in STEAM.md).
- **Steam** → App ID in `desktop/steam.config.json`; achievements in `src/content/achievements.ts` (must match Steamworks API names); release steps in STEAM.md.
- **View scale** → `WORLD_TARGET_H` / `UI_TARGET_H` in `view/viewport.ts`.

## Verification

- `npm install` clean; `npm run dev` boots with no console errors (black cover → loading bar → menu; no white flash, no stuck black screen).
- Play → scene runs; HUD reflects store updates; Menu round-trips destroy the Pixi app cleanly (no WebGL context warnings).
- Across window sizes and DPRs (1.0, 1.25, 2, 3) art and text stay crisp and panels fit (UI ≥ 690×430 UI px). In dev, `window.__rhune.reach()` lists whether every interactable is reachable from the spawn.
- `npm run build` passes (it type-checks first); `npm run preview` serves a working game; `dist/index.html` asset URLs start with `./`.
- Desktop: `npm run desktop` boots with no console errors (watch for CSP violations); closing the window writes `<userData>/saves/rhune_save_v1.json`; relaunch offers Continue. `npm run dist:linux` (or win/mac) produces a runnable `release/*-unpacked` app. Headless check: `xvfb-run` + Playwright `_electron` (pass `--no-sandbox` as root).
